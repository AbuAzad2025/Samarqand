# توثيق الأداء — معايير مقاسة

هذا الملف يوثّق قيماً سُجّلت فعلياً في هذه الجولة/الجولات السابقة، ويشرح كيفية إعادة قياسها. هي «معايير مقاسة»، ليست أهدافاً أو وعوداً. نطاق هذه المهمة توثيق فقط: لم تُعَد تشغيل الفحوص الكاملة عند كتابة الملف، ولم يُعدّل أي ملف آخر.

## 1) القيم المسجّلة

### Lighthouse — فئات الوصول وأفضل الممارسات وSEO

| الصفحة | Accessibility | Best Practices | SEO |
| --- | --- | --- | --- |
| الرئيسية `/` | 1.00 | 1.00 | 1.00 |
| صفحة المشروع `/projects/<slug>` | 1.00 | 1.00 | 1.00 |
| بقية الصفحات العامة | 1.00 | 1.00 | 1.00 |

- أخطاء Console المسجّلة على هذه الصفحات: **صفر**.
- مصدر القيم: تشغيل Lighthouse فعلي في الجولة الحالية/السابقة. يُعاد التحقق منها باتباع القسم 2؛ لا تُنسخ الأرقام هنا كتقدير لجولة جديدة.

### مهام JavaScript الطويلة — قبل تحسين الجولة الرابعة

- سُجّل **5 مهام طويلة** بمجموع زمني **نحو 370ms** قبل تحسين الجولة الرابعة.
- **المصدر هو trace المتصفح** (لوحة Performance → Long tasks)، **وليس نتيجة Lighthouse performance score**. لذلك لا تُقارن هذه القيمة بدرجة Performance ولا تُستبدل بها.
- لم تُسجّل قيمة جديدة بعد التحسين في هذا الملف؛ أي رقم لاحق يُضاف فقط بعد قياس فعلي.

## 2) كيفية إعادة القياس خطوة بخطوة

### أ) بناء الواجهة الأمامية

```powershell
cd frontend/samarqand
npm install          # مرة واحدة فقط عند الحاجة
npm run build        # أو: npm run check  (فحص أنواع + بناء)
```

حسب `frontend/samarqand/vite.config.ts` يكتب Vite الناتج في `website/static/website/samarqand_spa/`، ولا يلزم أمر Django منفصل.

### ب) التشغيل المحلي

```powershell
pip install -r requirements.txt
python manage.py migrate
.\run_local.ps1
```

- إذا كانت قاعدة البيانات المحلية فارغة، راجع أوامر البذر في `README.md`؛ لا تُدرج أي كلمة مرور أو مفتاح في هذا الملف أو في Git.
- افتح `http://localhost:<PORT>/` حيث `<PORT>` هو المنفذ المحلي الموضّح في `README.md` / `run_local.ps1`. تأكد من عدم وجود خادم آخر يعمل على المنفذ نفسه قبل التشغيل.

### ج) تشغيل Lighthouse

1. افتح المتصفح في نافذة خاصة لاستبعاد أثر التخزين المؤقت، وافتح العنوان المحلي أعلاه.
2. افتح أدوات المطوّر (F12) ← تبويب **Lighthouse**.
3. اختر فئات **Accessibility** و**Best Practices** و**SEO**. فئة Performance منفصلة ولا تُستخدم درجتها كدليل في هذا التوثيق.
4. ثبّت خيارات الجهاز/الشبكة كما كانت عند القياس الأصلي، ودوّنها مع النتيجة؛ لا تفترض إعداداً لم يُسجّل.
5. شغّل التحليل لكل صفحة على حدة: الرئيسية، صفحة مشروع، ثم بقية الصفحات العامة المراد التحقق منها.
6. سجّل القيم التي تظهر فعلياً، مع اسم الصفحة وتاريخ القياس. لا تكتب رقماً قبل ظهوره في التقرير.

### د) تسجيل trace المتصفح لمهام JavaScript الطويلة

1. في أدوات المطوّر افتح تبويب **Performance** وابدأ التسجيل.
2. أعد تحميل الصفحة ثم أوقف التسجيل.
3. في المخطط الزمني ضمن المسار الرئيسي (Main) ابحث عن **Long tasks**؛ عدّ الإدخالات وسجّل زمن كل واحدة ومجموعها إن وُجدت.
4. يمكن أيضاً مراقبة `longtask` عبر `PerformanceObserver` في الـ Console.
5. دوّن المصدر بوضوح: هذه مهام من trace المتصفح، وليست نتيجة Lighthouse performance score.

### هـ) فحص الاستجابة والصحة

1. افتح `http://localhost:<PORT>/health`؛ حسب `contracting_site/urls/_views.py` تُعيد نقطة النهاية استجابة JSON تحمل حقول `status` و`database`.
2. في تبويب **Network** تحقق من حالة الاستجابة الرئيسية وطلبات الصفحة، وراقب وجود طلبات `400`/`403`.
3. في تبويب **Console** سجّل أي أخطاء ظاهرة. القيمة المسجّلة سابقاً كانت صفر أخطاء؛ أي نتيجة جديدة تُدوّن كما تظهر.

## 3) قائمة تحقق لعدم التراجع

- [ ] **لا أسرار في Git:** لا مفاتيح ولا كلمات مرور ولا عناوين IP ولا بيانات اعتماد في الملفات المتتبعة؛ `.env.example` أمثلة فقط، و`db.sqlite3` غير متتبع. راجع `git status` و`git diff` قبل أي إضافة.
- [ ] **لا منافذ متعارضة:** لا تُشغّل نسختين من الخادم على المنفذ المحلي نفسه؛ أوقف أي خادم قائم قبل إعادة التشغيل، واستخدم المنفذ الموضّح في `README.md`.
- [ ] **لا ادعاءات AI/مجاني/فوري:** لا أرقام أو وعود غير موثّقة، ولا مقاييس خدمة مُخترعة؛ الأرقام المعروضة في الموقع مصدرها قاعدة البيانات الموثّقة وأمر `set_truthful_stats`، لا وعود تسويقية.
- [ ] **لا تغيير في البيانات الحقيقية:** لا تعديل على `db.sqlite3` أو بيانات البذر أو محتوى المشاريع؛ في هذه الجولة التغيير الوحيد المسموح هو هذا الملف.
- [ ] **الواجهة تعمل على RTL:** تحقق من `dir="rtl"` في `index.html`، من ترتيب العناصر واتجاه الأزرار والنصوص، ومن اللقطات على مقاسات مختلفة في `qa/screenshots/` و`qa/viewport_report.json`.

> عند إضافة أي قيمة جديدة إلى هذا الملف، اذكر مصدرها وطريقة قياسها؛ لا تضف رقماً أو وعداً لم يُقس.
